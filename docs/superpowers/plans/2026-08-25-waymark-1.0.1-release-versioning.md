# Waymark Community 1.0.1 Release Versioning Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prepare an independently reviewable Waymark Community 1.0.1 maintenance candidate from accepted commit `d4476ffd2dff62f7ac411f1a8a12b5f2597ad1fb` without altering or publishing the existing public 1.0.0 release.

**Architecture:** A tracked root `VERSION` becomes the default release-builder input, while an explicit `--version` remains available for exact historical-package fixtures. Release-facing documentation and tests identify 1.0.1, and the production package matrix uses the actual immutable GitHub 1.0.0 artifacts to prove update and rollback behavior for both deployment layouts. Stable-feed proposals remain external review artifacts and use one signed feed per deployment layout because the accepted updater schema verifies one package per configured feed URL.

**Tech Stack:** PHP 8.3+, Laravel 13, PHPUnit, Node.js tooling tests, GitHub CLI, MySQL 8.4, MariaDB 11.4, Playwright, OpenSSL SHA-256 signing.
